# F29 manual checks: GitHub connector

Needs a fine-grained GitHub token in `.env.local` as `GITHUB_TOKEN=…` (see HUMAN_TODO) and `api.github.com`
allowed in the sandbox network policy.

1. `SMOKE=1 pnpm smoke:github`: runs `gh auth status` in a throwaway bot container with `GH_TOKEN`. Expect
   "Logged in to github.com". No engine is called.
2. `pnpm dev`, open Settings → Connectors. The GitHub card says **token set**. Tick **Enable GitHub** and one bot.
3. Open that bot's Terminal tab and run `gh auth status`: signed in. In a bot that is not ticked: `echo $GH_TOKEN` is
   empty (open a new terminal tab after changing the setting; a running shell keeps its env).
4. Open `/home/bot/CLAUDE.md` in the enabled bot's Files tab: it has a `## GitHub` section; the other bots' files do not
   (rendered before each run and when the computer starts).
5. Ask the enabled bot: "List the open issues in <owner>/<repo>." It runs `gh issue list` without asking.
   Then: "Open a PR that fixes a typo in the README." It must call `request_approval` before `git push` / `gh pr create`;
   the request shows in the bell. Deny it and check the bot stops.
